## Imported Claude Cowork project instructions

Develop a website to manage the Pet Dental Clinic Workflow. Using the clinic's forms (in `reference/forms/`), build a web app that makes the workflow for each patient visit easier. It will mostly be used on an iPad, so it should look best there, but it must also work in a desktop browser.

## Project notes

- Single-file app: everything is in `index.html` (inline CSS/JS, no framework, no build). Keep it that way, and make sure it still works when opened straight from disk.
- iPad first (Safari, usually added to the Home Screen). Keep touch targets ≥ 44px, inputs at ≥ 16px font (smaller makes Safari zoom in), and use hover styles only inside `@media (hover:hover)`.
- Workflow steps (`STEPS`): checkin, auth, exam, anes, dental, discharge. Each maps to a form in `reference/forms/`. `missing()` defines what each step needs before it counts as complete.
- Data: localStorage keys `pdc-data-v1` (data, with `sync.rev`), `pdc-sync-v1` (GitHub settings and `baseRev`), `pdc-token-v1` (token). `pdc-conflicts-v1` (this device's list of fields changed on two devices at once). Never merge these keys and never export the token. Increase `rev` only when the stored data actually changes.
- No patient data in this repo. `.gitignore` blocks `*.json`, spreadsheets and `reference/`. The example patients (Biscuit, Miso) are generated in code and flagged `sample: true`.
- Sync is automatic (`syncNow`, `scheduleSync`): a three-way merge (`merge3`) of this device, GitHub and the last common copy, read back from GitHub by `cfg.baseSha`. Records with ids merge by id, other arrays by position, and same-field clashes keep this device's value (or GitHub's when there's no common copy) and are recorded. Example patients (`sample: true`) never sync. Don't redraw while someone is typing or signing (`busyEditing`).
- Medication labels live in the discharge step (`v.discharge.rx`). Label settings are `data.settings.labels`; the formulary is the built-in `RX_SEED` until someone edits it, and only then is it stored in `data.settings.formulary` (so just opening Settings never bumps `rev`).
- Printouts should look like the paper originals, and every form is a replica: the Word forms (`FORM_ART`: New Patient, Authorization, Exam, Treatment Notes, Discharge routine/extractions) and dental charts (`CHART_ART`) are the clinic PDFs converted to SVG with field positions, drawn at their original page positions inside the 12 mm print margins; the landscape monitoring form (rebuilt from the .xlsx at its 46% print scale, rotated onto a portrait page) is built in code. Treatment notes go in the treatment sheet's empty bottom rows. On the printed chart an extracted tooth gets an X and a missing tooth (`/`) a slash across each drawing of that tooth (`toothMark`, using `CHART_TEETH`: tooth boxes in page units, measured from the chart pictures); the table row then leaves out "EXT" and "/" but keeps the extraction method. Mass marks from the exam body map (`v.exam.masses`, `{id,map,x,y,note}` in the 185 × 145 figure's units) print as numbered rings on the exam sheet's cat/dog figures (a drawn ferret covers them for ferrets). Drawings are pre-decoded (`preloadArt`) so `window.print()` runs inside the tap (Safari needs that); `imagesReady` waits only for pictures not yet decoded. In the iOS Home Screen app `window.print()` does nothing, so every print goes through `sendToPrinter`, which there builds a PDF of page pictures (`printoutPDF`) and shares it (Print is in the share sheet). Values are written in Arial on the blanks; choices are ticked, circled or marked X as on paper.
- Dental charting is tap-only: measurements (`P`, `GR`, `RE`, `AL`, stored as strings in `teeth[n].codes`) come from a number pad, not inputs, so the keyboard never opens. They are entered the way they are said, number → type → site ("3 mm pocket mesial"): `ui.mmPend` holds the number, the type button saves it, and for a pocket `ui.mmLast` lets a site tap move it to that site; with the next-tooth option, the next number after a pocket moves on a tooth. Pockets by site are in `teeth[n].pockets` (`M`, `D`, `B`, `L`; per AVDC, `B` reads "V" for vestibular and `L` reads "Pal" on maxillary teeth), alongside the plain `codes.P`; `toothStr(t,n)` needs the tooth number for that label. With a tooth selected, `#teditor.cm` is a fixed full-screen charting mode (top bar, the chart moved in from the page, options in CSS columns inside `.cm-scroll`); keep every view fitting a 1024×768 iPad without scrolling. The dental step has three views (`ui.dview`, saved per device): oral exam (`ORAL_GROUPS`, number pad, GI/CI), radiographs (`RAD_GROUPS`, overall stage) and treatment (`TX_GROUPS`, AVDC procedures in `teeth[n].tx`; an extraction method sets `ext`; `procSummary` writes the procedure summary that prints first in the chart's Extractions box). `RAD_SET` decides which view a code belongs to (`toothPart`), and "Clear" only clears the current view's findings. An oral mass's position relative to its tooth is `teeth[n].omPos` (`R` rostral, `C` caudal, absent = at the tooth) its side is `teeth[n].omSide` (`V` vestibular, `L` lingual/palatal) and its size is `teeth[n].omSize` (cm, a string); all are cleared with OM. A persistent deciduous tooth is the oral-exam code `DT/P` on the permanent tooth's position (only where a deciduous predecessor exists, `hasDeciduous`); it reads as the deciduous number (`decNum`: +400, e.g. 104 → 504), and its extraction method is `teeth[n].dtx` (treatment view), which counts in `extractions()` and `procSummary` as 5xx–8xx without marking the permanent tooth extracted. Every charting button carries its definition as a tooltip (`CODE_DEF`/`codeTip`; treatment buttons use `TX_NAME`/`TX_DEF`); since the iPad has no hover, press-and-hold (450 ms, touch only) shows it in a `.tip` bubble and swallows that tap. Abbreviations follow the AVDC case-log list (bone graft is `GF/B`; old `BG` entries are renamed in `ensureShape`). Per-tooth radiograph codes and PD1–PD4 stages are plain codes (one stage per tooth via `EXCL`); `v.dental.stage` is the whole-mouth stage. The clinic always takes full-mouth radiographs, so there is no radiographs-taken field (old visits may still carry an unused `v.dental.rads`).
- Drug concentrations come from the clinic treatment sheet (`DRUGS`). Dexmedetomidine doses are in mcg/kg; the others are in mg/kg.
- Tests: `npm install && npm test` (jsdom). Run them after every change. When one fails, decide whether the test or the app is wrong.
- Publishing: use `../_github-toolkit` (`scan.sh`, `publish.sh`, `update.sh`) with this folder's `.github-publish.conf`.
